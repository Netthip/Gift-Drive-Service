# GPR Multi-Agent Customer Service — รายงานผลการตรวจสอบความเป็นไปได้ (รอบที่ 1)

วันที่ตรวจสอบ: 25 พ.ย. 2026 · ขอบเขต: ตรวจสอบและพิสูจน์ความเป็นไปได้เท่านั้น ไม่ได้ซื้อบริการ ไม่ได้ส่งข้อความหาลูกค้า

ระดับความน่าเชื่อถือ: **ยืนยันแล้ว** = เอกสารทางการ/ทดสอบเอง · **น่าจะใช่** = แหล่งรองที่น่าเชื่อถือ · **ไม่แน่นอน** = ต้องทดสอบจริง

---

## สรุปผู้บริหาร (อ่านส่วนนี้ก่อน)

1. **Bo (ChatGPT) กับ Jiho (Codex) ยังคุยกันโดยตรงไม่ได้** — ไม่มีฟีเจอร์ native, ไม่รองรับ A2A, และคำสั่ง `codex mcp-server` ที่เคยใช้เชื่อม ถูกถอดออกแล้ว (ยืนยันแล้ว)
2. **ทางที่ใกล้ "อัตโนมัติ" ที่สุดโดยไม่ต้องพัฒนาเอง** คือใช้ช่องทางกลาง (Slack / Gmail / GitHub) + **Event-triggered Task ของ ChatGPT** ให้ Bo ทำงานเมื่อมีข้อความใหม่ และให้ Jiho อ่าน/เขียนช่องทางเดียวกันผ่าน MCP หรือสคริปต์ `codex exec`
3. **ถ้า Bo และ Jiho อยู่บัญชีเดียวกัน** จะได้ฟีเจอร์ native เพิ่ม (Dots, Remote control, งานต่อเนื่องบนเครื่อง Windows) แต่ **ห้ามแชร์บัญชีให้คนอื่นใช้** ตามข้อกำหนด OpenAI → ทางถูกต้องคือ **ChatGPT Business (2 ที่นั่งขึ้นไป ~$20–25/คน/เดือน)** ซึ่งยังได้ "ไม่นำข้อมูลไปเทรนโดยค่าเริ่มต้น" ด้วย
4. **ความเสี่ยงสูงสุดไม่ใช่เทคนิค แต่เป็นกฎของ Xiaohongshu** — มีประกาศ (มี.ค. 2026) ห้ามบัญชีที่ใช้ AI/เทคนิคจำลองการโต้ตอบเหมือนคนในแชทส่วนตัว และข้อตกลงผู้ใช้ห้ามใช้ซอฟต์แวร์บุคคลที่สาม → **การตอบอัตโนมัติจริงในระดับ production มีความเสี่ยงถูกแบนสูง**
5. **ข้อเสนอ MVP**: AI เป็น "ผู้ช่วยร่างคำตอบ" — คนเป็นผู้กดส่งเสมอ, ใช้กล่องข้อความทางการ (私信通 / pro.xiaohongshu.com บนเว็บ) แทน Phone Link ในระยะยาว, ปิดการเทรนข้อมูล และลบข้อมูลส่วนบุคคลก่อนส่งให้ AI

## Phase 2: Phone Link Proof of Concept

**สถานะ: เตรียมชุดทดสอบเสร็จแล้ว ยังไม่ได้ทดสอบบนเครื่องจริง** (ไม่มีเครื่อง Windows เชื่อมกับ session นี้ — ไม่มีการแต่งผลทดสอบ)

ไฟล์: `poc/phone-link/xhs_draft_poc.py` + `requirements.txt` — ให้ Jiho หรือผู้ใช้รันบน Windows

| ขั้น | วิธีหลัก | วิธีสำรอง | ความเป็นไปได้ (ก่อนทดสอบ) |
|---|---|---|---|
| 1 เปิด Phone Link | `start ms-phone:` | `explorer shell:AppsFolder\<AppID จาก Get-StartApps>` | สูง |
| 2 เปิด Xiaohongshu | Ctrl+3 (แผง Apps) แล้วคลิก "小红书/RedNote" ผ่าน UI Automation | เปิดเอง / ปักหมุดใน Start | สูง (ต้องกด "Start now" บนมือถือ) |
| 3 เข้าหน้าข้อความ | OCR หาคำว่า "消息" แล้วคลิก | คลิกเอง | ปานกลาง |
| 4 อ่านข้อความจีน | จับภาพเฉพาะหน้าต่าง XHS + OCR (RapidOCR ฟรี ในเครื่อง) | ส่งภาพให้ Codex ดู (`view_image`) | ปานกลาง — หน้าต่าง mirror เป็นภาพวิดีโอ อ่านข้อความผ่าน UI Automation ไม่ได้ |
| 5–6 ส่งให้ Agent / รับคำตอบ | ไฟล์ `out/message.json` → Agent เขียน `out/reply.txt` | คัดลอกเอง | สูง |
| 7 พิมพ์โดยไม่กดส่ง | วางผ่านคลิปบอร์ด (ต้องเปิด cross-device copy & paste) | ส่งตัวอักษร Unicode | **ไม่แน่นอน** — ภาษาจีนผ่าน IME มือถือเป็นจุดเสี่ยงที่สุด |

**ข้อค้นพบจากการวิจัย Phone Link:**
- ฟีเจอร์ Apps ยังมีอยู่ (ไม่ถูกยกเลิก) ต้องใช้ Android 10+ ที่มี Link to Windows, Wi-Fi เดียวกัน, เปิดพร้อมกันได้สูงสุด 5 แอปบน Samsung (ยืนยันแล้ว) · Samsung DeX for PC ถูกยกเลิกตั้งแต่ One UI 7
- เมาส์/คีย์บอร์ดใช้ได้ (คลิก = แตะ, คลิกขวา = ย้อนกลับ) แต่ **Microsoft ไม่ได้รับรองการพิมพ์ภาษาจีน** → ใช้ cross-device copy & paste (Samsung One UI 2.1+) เป็นทางหลัก (ยืนยันแล้ว)
- โทรศัพท์และ PC ต้องปลดล็อก, อาจมีปุ่ม "Start now" บนมือถือทุกครั้งที่เริ่ม mirror, ใช้ผ่าน RDP ที่ย่อหน้าต่างไม่ได้
- แอปที่บล็อกการแคสต์จะเป็นจอดำ — ต้องทดสอบว่าหน้าแชท XHS บล็อกหรือไม่
- ทางเลือกที่เสถียรกว่า: **scrcpy** (`--keyboard=uhid` พิมพ์จีนได้, ซิงก์คลิปบอร์ด) + `uiautomator dump` อ่านข้อความเป็นตัวอักษรจริง — แต่ต้องเปิด USB debugging และเสี่ยงต่อการตรวจจับมากกว่า

กลไกความปลอดภัยในสคริปต์: หยุดยืนยันทุกขั้น, **ไม่กด Enter/ส่งเด็ดขาด**, จับภาพเฉพาะหน้าต่าง XHS, เลื่อนเมาส์ไปมุมจอเพื่อหยุดฉุกเฉิน, บันทึก log + ภาพหลักฐานทุกขั้น

**ทางเลือกที่ดีกว่า Phone Link (แนะนำให้ทดสอบคู่กัน):** กล่องข้อความทางการบนเว็บ `pro.xiaohongshu.com` (私信通 PC) — เป็นหน้าเว็บ อ่านข้อความเป็นตัวอักษรได้จริง ไม่ต้อง OCR และเป็นช่องทางที่แพลตฟอร์มรองรับ (ต้องเป็นบัญชีองค์กรที่ยืนยันแล้ว)

### อัปเดต: ผลทดสอบจริงโดย Bo (ChatGPT Plus + Computer Use)

| การทดสอบ | ผล |
|---|---|
| เข้าถึง Windows | ✅ สำเร็จ |
| เชื่อมต่อ Samsung S25+ ผ่าน Phone Link | ✅ สำเร็จ |
| เปิด Xiaohongshu (rednote) | ✅ สำเร็จ |
| อ่านบทสนทนาภาษาจีน (จากภาพหน้าจอ) | ✅ สำเร็จ |
| พิมพ์ตอบลูกค้า | ⏳ ยังไม่ได้ทดสอบ |
| ส่งข้อความจริง | ⛔ ยังไม่ส่ง (ตั้งใจ) |

**ต้นทุนโควต้า:** การให้ Bo มองภาพหน้าจอทุกครั้งกินโควต้าสูง (บัญชี Plus มีเพดาน 5 ชั่วโมงและรายสัปดาห์) → ให้เครื่องอ่านเองด้วย `poc/phone-link/xhs_reader.py`:
จับภาพเฉพาะหน้าต่าง XHS → OCR ในเครื่อง (ไม่ใช้โควต้า AI) → ส่งเฉพาะบรรทัดใหม่เป็นตัวอักษรไปที่ `out/inbox.jsonl` → Bo อ่านแค่ข้อความ
สคริปต์นี้อ่านอย่างเดียว ไม่คลิก ไม่พิมพ์ และลบภาพทิ้งหลัง OCR

| วิธีทำงาน | โควต้า |
|---|---|
| Bo มองภาพหน้าจอ + คลิกหลายรอบ | สูง |
| xhs_reader อ่านในเครื่อง แล้วส่งข้อความให้ Bo | ต่ำมาก (เฉพาะส่วนแปลและร่างคำตอบ) |

**นโยบายตอบ 2 กลุ่ม (ตามที่ Bo เสนอ) + เงื่อนไขเพิ่ม:**
- คำถามทั่วไป (ราคา เส้นทาง กระเป๋า เงื่อนไข): ตอบตามมาตรฐาน GPR — **ตัวเลขต้องมาจากตารางราคา/ตารางรถเท่านั้น** ไม่ใช่ความจำของ AI และในช่วงแรกยังเป็น "ร่าง แล้ว Gift กดส่ง" เพราะกฎ 小红书 ห้ามใช้ AI จำลองการโต้ตอบในแชท
- กรณีพิเศษ (ส่วนลด ยืนยันคิว มัดจำ เส้นทางนอกมาตรฐาน): ส่งเรื่องให้ Gift ทุกครั้ง

## Phase 3: สถาปัตยกรรม Multi-Agent ที่เสนอ

```
                  ┌──────────── Bo (Lead, ChatGPT) ────────────┐
ลูกค้า → [DM] →   │ วิเคราะห์ ตัดสินใจ อนุมัติร่าง                 │
                  └───────┬───────────────────────────▲────────┘
                          │ งาน (task)                │ ผลลัพธ์
                    ┌─────▼──── Shared Channel ───────┴─────┐
                    │  Slack channel #gpr-tasks (หรือ repo)  │
                    └─────┬─────────────────────────────────┘
        ทำงานขนานได้       │
  ┌──────────┬──────────┬─┴────────┬──────────┐
  Chinese    Pricing    Booking/   Customer   QA Agent
  Language   Agent      Calendar   Data       (ตรวจโทน ราคา
  Agent                 Agent      Agent       ข้อมูลส่วนตัว กฎ XHS)
  └──────────┴──────────┴──────────┴──────────┘
                          │ ร่างที่ผ่าน QA
                ┌─────────▼──────────┐
                │ Screen Queue (FIFO)│  ← ทีละงานเท่านั้น
                └─────────┬──────────┘
                    Jiho (Computer Use, Windows)
                    อ่าน DM / พิมพ์ร่าง — ไม่กดส่ง
                          │
                     มนุษย์ตรวจและกดส่ง
```

- **งานขนาน:** ภาษาจีน, ราคา, ตารางจอง, ข้อมูลลูกค้า ไม่ขึ้นต่อกัน → Bo สั่งพร้อมกันได้ (ในระยะแรกเป็น "บทบาท/คำสั่ง" ภายในแชทของ Bo หรือ skill ของ Codex ไม่จำเป็นต้องเป็นบริการแยก)
- **งานลำดับเดียว:** ทุกอย่างที่แตะหน้าจอ/คีย์บอร์ดผ่าน Screen Queue ตัวเดียว ใช้ lock file (`queue/screen.lock`) — Jiho หยิบงานทีละชิ้น ทำเสร็จจึงปลด lock
- **QA เป็นด่านบังคับ** ก่อนเข้าคิวหน้าจอ: ไม่มีเบอร์/WeChat/ลิงก์, ราคาตรงตาราง, ภาษาสุภาพ, ไม่มีข้อมูลลูกค้าคนอื่น
